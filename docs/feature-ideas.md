## 採用したもの (C / D) の理由

- **穴が広い**: C だけで G3〜G6 の4件を一度に埋められる。D は G7 を単独で埋める。
- **依存が閉じている**: どちらも VOICEVOX Engine・音声接続まわりに触れない。
  変更は `index.js` のイベント判定・`store.js` の永続化・新コマンド1本ずつに収まり、
  `player.js` の繊細な接続管理（`entersState` 後にセッション登録、`WeakSet` でリスナー二重登録防止など）に手を入れずに済む。
- **相互補完**: C は「何を・どう読むか」、D は「誰の何を読まないか」。
  どちらも `MessageCreate` の入口判定に手を入れるため、まとめて設計したほうが判定順序の矛盾が起きない。
- **既存データと後方互換**: 既存の `data/*.json` を壊さずに拡張できる（各 spec の移行方針を参照）。

## 見送ったものの補足

- **A (`/skip`)**: 実装は 30 行程度で終わるが、C/D と違って設計判断がほぼ無い。
  C/D の実装ついでに追加してよい。仕様は「`/skip [all:bool]` → `player.skip()` を呼び、
  セッション無しなら ephemeral で通知」だけで足りる。
- **B (`/sound`)**: 添付ファイルの保存先・容量上限・拡張子検証・`data/` の肥大化・
  誰が消せるかの権限設計が必要で、C/D と比べて検証項目が跳ね上がる。C/D の後に単独で扱う。
- **F (分割読み上げ)**: 50文字上限は「長文で他の人の発言が詰まる」のを防ぐ意図的な制限。
  分割するとキュー滞留時間が伸び `MAX_QUEUE` の意味も変わる。C で `max_length` を
  サーバーごとに調整できるようにするのが先。

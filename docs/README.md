## 読み方

- `spec-*.md` は「仕様 → 受け入れ条件 → 実装方針」の順。実装前に受け入れ条件まで読むこと。
- 2つの spec は `MessageCreate` の同じ判定パイプラインに手を入れる。
  統合後のパイプライン定義は [spec-ignore.md の「4. 読み上げ判定パイプライン」](spec-ignore.md#4-読み上げ判定パイプライン統合後)に一本化してあるので、
  どちらを先に実装する場合でもそちらを正とする。
- 実装時は `CLAUDE.md` の「設計上のポイント」も更新する（前提が変わる箇所を各 spec に明記してある）。
